# 관내 피그 1D 운동 모듈

상태: 구현·시험 시나리오 작성 완료. 수치 검증은 누리온 실행 대기이며, 이번 로컬 작업에서는 pytest, 벤치마크, 수치 smoke를 실행하지 않았다. 정적 검사 통과가 물리 검증을 의미하지 않는다.

## 제공 기능과 모델 소유권

조사한 기존 캐시의 equipment/transient/hydraulics Python 소스에서 재사용 가능한 피그 운동 엔진을 찾지 못했다. 이 모듈은 사용자 공급 압력 경계와 기계 파라미터를 조합한 강체 1D 운동 방정식을 SciPy `solve_ivp`의 RK45로 적분한다. 새로운 수치 적분기를 작성하지 않았다. 외부 유동 엔진이 예측한 압력을 입력할 수 있지만, 피그 이동에 따른 압력 변화나 유체 질량 보존을 내부에서 예측하지는 않는다.

좌표 x는 upstream 포트에서 downstream 포트로 증가하며, 관 경계는 0과 length_m이다. 두 압력은 모두 절대압 Pa이다. 구간별 압력 힘은 유효 면적 곱하기 upstream에서 downstream을 뺀 압력이다. 경사는 양의 x 방향으로 높아지는 각도 rad이며, 중력의 축방향 성분은 반대 방향이다. 외력은 양의 x를 기준으로 부호를 포함한다. 질량 kg, 면적 m², 힘 N, 속도 m/s, 일 J를 사용한다.

마찰은 사용자가 지정한 정지마찰 한계 N과 운동마찰 N, 그리고 속도 제곱 저항 계수 N·s²/m²로 구성된다. 중력이나 압력으로부터 접촉 수직력을 자동 추정하지 않는다. 따라서 이 마찰 입력은 재료 마찰계수와 다르다. 정지마찰은 운동마찰 이상이어야 한다. 계수·면적·질량·경사에는 실제 근거와 검토가 필요하며 예제 수치를 설계값으로 쓰지 않는다.

## 데이터와 API 계약

`PigBoundaryWindow`는 일정 시간 동안 일정한 upstream/downstream 압력 및 외력을 제공한다. provider_id, provider_version과 evidence_id를 함께 기록한다. 공급자의 원본 관측/계산 근거, 재사용 조건, 파일 해시는 context의 `EvidenceRef`에 넣을 수 있다. 데이터가 없을 때 None을 쓰며, 알려진 외력 없음은 0으로 지정한다. 압력의 시간 보간이나 관측 오차 추정은 이 API에 포함하지 않는다. 공급자 이력을 작은 일정 시간 구간들로 변환할 경우 그 근사 오차를 별도 검토해야 한다.

1. `PigMotionRequest`에 기계 파라미터·초기 위치/속도·경계 구간·검토 예산을 지정한다.
2. `runtime_metadata()`의 SciPy/NumPy/Python 버전과 solver/RK45/adapter 소스 해시를 실제 검토 시점에 `runtime_pins`로 고정한다.
3. 네 `REVIEWS`에 검토 여부 및 실제 근거 ID를 연결한다. 모든 근거는 실제 `RunContext.evidence` 중 고유 ID에서 선택한다.
4. `boundary_metadata(request)`를 context.metadata의 pig_motion_boundary 키에 기록한다. 이 계약은 자산, 시계, 포트, 요청 전체, provider 구간을 바인딩한다.
5. `evaluate_pig_motion(request, context)`로 기록을 생성한다. 미검토/누락 입력은 needs_data로 반환하고 solver에 접근하지 않는다. pin/context 불일치는 입력 오류로 예외를 낸다.
6. `verify_pig_motion_record`는 digest 확인 이후 현재 solver로 실제 재실행한다. 비용과 작업 예산은 원 계산과 같다.
7. `to_signal_frames`는 실제 context와 재실행 검증된 computed_diagnostic 기록만 변환한다. 시간 경계의 좌·우 기록은 raw history에 유지하고, 신호에는 동일 시각의 마지막 기록을 선택한다.

`examples/pig_motion.py`는 새로 작성한 합성 데이터이다. 기본 실행은 미검토 needs_data 결과를 만든다. `make_case(reviewed=True)`는 시험 작성 편의 기능으로, 현장 검토가 이루어졌다는 증거가 아니다.

## 운동 상태와 사건

정지 상태에서 구동력 크기가 정지마찰 한계 이하이면 마찰 반력과 구동력이 상쇄되어 멈춘다. 한계를 넘으면 구동력 방향으로 출발한다. 움직이는 동안 운동마찰과 속도 제곱 저항은 해당 운동 방향에 반대다. 속도 영점은 SciPy 사건으로 검출하고, 사건 시각에서 정지마찰 조건을 다시 판단한다. 반대 구동력이 충분하면 반대 방향으로 새 구간을 시작한다.

속도 영점의 원래 root residual은 transitions에 보존한다. 그 잔차가 사용자가 검토한 velocity_atol_m_s를 초과하면 거부한다. 허용 범위 안에서만 다음 구간 초기 속도를 정확한 0으로 재설정한다. 이 재설정의 작은 운동량·에너지 차이도 이후 누적 수지에 드러나며 무조건 성공으로 바꾸지 않는다. solver의 사건 탐색을 위해 현재 운동 방향의 연속 방정식을 시험 단계에 연장하지만 사건 이후 그 가지를 실제 궤적으로 채택하지 않는다.

상·하류 끝점 도달은 계산 종료다. 도달 직전 운동에너지를 반환하되 충격력, 충돌 시간, 반발, 정지 장치의 변형 및 압력파를 예측하지 않는다. 초기 경계점에서 바깥쪽 속도를 주면 거부한다. 경계점의 정지 상태가 바깥쪽으로 출발하려 하면 경계 종료를 기록한다. 역방향 이동은 관내 범위에서 허용된다. 위치는 숨겨서 clipping하지 않으며 수락 상태의 root 오차와 position_atol_m에 따른 도메인 판정을 기록한다.

## 수지·수치 정책

질량은 사용자 지정 강체 질량으로 고정된다. 질량 유출입·마모·침적물 축적을 적분하지 않는다. 상태는 위치, 속도, 압력 일, 중력 일, 외력 일, 마찰 일, 순충격량이다. 힘별 일의 시간 미분은 해당 힘과 속도의 곱이며 순충격량의 시간 미분은 합력이다. 동일 수락 적분으로 운동에너지 변화와 일 합계, 운동량 변화와 순충격량을 교차 확인한다. 합력과 가속도도 history에 기록한다. 이 수지 검사는 제공된 힘 모델에 대한 수치 일관성이며, 실제 마찰이나 압력의 정확성을 입증하지 않는다.

정지 중 정지마찰 반력의 일은 0이고 합력/순충격량 증가도 0이다. 압력이나 외력 경계가 바뀔 때 임의 충격량을 추가하지 않는다. 불연속 경계는 정확히 시간 구간을 나누고 상태를 연속으로 넘긴다. 수지 허용오차는 절대 예산과 상대 예산을 결합한다. 범위를 벗어나면 diagnostic_rejected이며, 적분 실패·작업 예산 초과는 out_of_scope로 명시하고 부분 궤적을 성공 결과로 남기지 않는다.

RK45의 상대오차, 위치·속도·일·충격량별 절대오차, 최대 스텝을 명시적으로 제공한다. 최대 기간, RHS 호출 수, 사건 수를 제한하고 clock에서 표현할 수 없는 구간 경계는 거부한다. 사건 검출은 스텝 내 부호 변화에 의존하므로 최대 스텝과 허용오차에 대한 수렴 검토가 필요하다. [SciPy 공식 solve_ivp 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html)에 solver 오차·사건 계약이 설명되어 있다.

## 누리온 검증 계획

`tests/test_pig_motion.py`에 미검토 차단, context/비유한 복사 입력, 기계 도메인, 일정 가속도의 해석해, 정지마찰 임계값과 출발, 정지 후 역방향의 구간별 해석해, 끝점 도달 시각/에너지, 속도 제곱 저항의 tanh 해, 기록 변조/pin 불일치, 작업 예산 거부 시험을 작성했다. 아직 실행하지 않았다. 검증 로그에는 source/environment pin과 테스트 pass/fail/skip을 각각 남겨야 한다.

후속 검증에는 최대 스텝·허용오차 수렴, 음의 경사/중력·외력 상쇄, 긴 정지 구간, 양끝점과 동시 속도영점, 매우 짧은 운전 구간, 검토 범위 경계값, 독립 위치·압력 관측과 비교가 필요하다. 자료가 확보되기 전 calibration이나 독립 validation으로 표시하지 않는다.

## 원소유 유동 모듈 확장 요청

유동 모듈이 피그와 깊게 연동하려면, 이동 경계 앞뒤 상태를 동일 clock/asset/port 계약으로 조회하고 수락된 피그 위치·속도에서 유체 질량·에너지 장부를 확정하는 순수 평가/확정 분리 API가 필요하다. trial 단계에서 영구 상태를 바꾸지 말아야 한다. 압력파와 누설, bypass, 유체 압축성, 다상 슬러그, 벽면 접촉·변형·곡관 및 충돌을 추가할 때는 각각 소유 모델과 독립 근거를 제공해야 한다. 새 관계식을 추정해 현재 어댑터에 임의로 내장하지 않는다.

## 공개 배포

정적 교차검토 보강: `maximum_events`와 `transition_count`는 속도영점뿐 아니라 기록된 breakaway/stuck 전이도 포함한다. 속도영점의 허용오차 내 reset은 전후 상태를 모두 장부에 남기고 수치 reset의 에너지/운동량 변화를 전이 기록에 별도로 보존한다. 이를 물리 마찰 일이나 외력 충격량에 몰래 더하지 않는다. 마지막 시간창 끝에서 reset이 발생해도 최종 상태를 동일한 실제 일/충격량 수지로 검사하며 허용 수지를 넘으면 `diagnostic_rejected`이다. 이 보강의 회귀 시험은 작성했으며 아직 실행하지 않았다.

문서·주석·합성 예제는 독립 작성했으며 표준 문장·외부 수치표·공급업체 마찰표를 내장하지 않았다. SciPy의 BSD-3-Clause 및 설치된 의존성의 실제 라이선스 고지 조건을 보존해야 한다. 측정 자료를 추가할 때는 각 EvidenceRef에 원본 라이선스와 제약을 유지한다. 현재 결과는 유체 EOS를 사용하지 않으므로 물성 기준은 '사용자 압력 공급, 유동 피드백 없음'으로 명시한다.
# 수신부 도착 시간·속도 판정 추가

`assess_receiver_arrival(record, request=q, context=c, earliest_time_s=...,`
`latest_time_s=..., maximum_arrival_speed_m_s=..., receiver_evidence_id=...)`는
기존 피그 궤적을 실제 요청·문맥으로 재생 검증하고 하류 끝점 도착을 판정한다.
시간 한계는 `q.start_time_s`와 같은 절대 시계 좌표이고 속도는 m/s이다.
수신부 한계의 근거 ID는 실제 문맥에 있어야 한다. 시간 역전·bool·비유한·음수
한계는 거부한다. 도착 시간과 속도가 모두 한계 안이면 `within_declared_limits`,
하나라도 벗어나면 `outside_declared_limits`다. 계산 기간 중 도착하지 않으면
`not_arrived_within_simulated_horizon`와 null 도착값을 반환한다. 미계산 궤적은
`needs_data`로 남긴다. 기간 밖 미래 도착, 수신부 포획·충격 흡수·구조 건전성과
실패확률을 추정하지 않는다. `verify_receiver_arrival_assessment(assessment,
pig_record, request=q, context=c)`는 판정 digest, source 궤적의 실제 재생,
요청·문맥 바인딩 및 한계값을 다시 계산해 판정 결과까지 재검증한다. 변조된
assessment를 성공으로 취급하지 않는다. 이 추가 기능의 회귀는 작성했고 누리온
실행 대기다.
