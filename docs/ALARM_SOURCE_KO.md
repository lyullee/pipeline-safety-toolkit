# 공개 공정 자료의 선언 경보 정책 재생

`scripts/check_alarm_source.py`는 이미 확보한 BattLeDIM 2018 SCADA 첫 864행을
기존 `process_monitoring.events.AlarmPolicy`에 전달한다. `alarm_exchange.replay_alarm`
경계를 통해 원 정책의 지속 시간·회복·시각 공백·래치 상태를 보존하는 자료 적용이다.
새 누설 탐지기를 학습하거나 사람의 경보 대응 성능을 추정하는 작업은 아니다.

## 자료와 검증 범위

자료는 Stelios G. Vrachimis 외 공동저자의
[BattLeDIM v1](https://doi.org/10.5281/zenodo.4017659), CC BY 4.0이다.
가상 L-TOWN 관망에서 생성한 모의 관측이며 실제 배관의 현장 계측으로 표시하지
않는다. 첫 구간만 재생하며, 같은 관망의 반복 시간 행을 독립적인 물리 시험으로
세지 않는다. 2018년과 2019년이 서로 독립적인 설비라는 가정도 하지 않는다.

읽기 전에 `2018_SCADA_Pressures.csv`, `2018_SCADA_Flows.csv`,
`2018_SCADA_Levels.csv`, `README.txt`의 전체 크기와 카탈로그에 기록된 공급자
MD5를 확인한다. 현재 SHA-256도 별도로 기록하고 실행 후 같은 파일들을 다시
확인한다. MD5는 공급자와의 파일 일치 확인이고 SHA-256은 이 실행의 원본 계보다.
원 자료를 다른 값으로 고치지 않는다.

기존 `loaders.iter_battledim_frames`가 세 SCADA 표의 같은 시각을 확인하고
864행을 읽는다. 사용 채널은 다음과 같이 고정한다.

| 채널 | 원 자료의 뜻과 단위 | 이 적용에서의 역할 |
|---|---|---|
| `pressure_head:n1` | 노드 n1의 압력 수두, m | 낮은 압력 수두 점수의 유일한 입력 |
| `volume_flow:PUMP_1` | 펌프 관로 유량, 원 m³/h를 기존 loader에서 m³/s로 환산 | 같은 시계의 맥락·품질 확인만 수행 |

수위 표는 기존 loader의 공통 시각 검증을 위해 읽으며 수위나 유량을 점수에
합치지 않는다. 압력 수두 m를 절대압력 Pa로 바꾸지 않는다. 이를 위해 필요한
밀도·중력·압력 기준을 새로 가정하지 않는다. 유량 환산은 `1/3600`이고 원
수치의 물리 의미를 바꾸지 않는다.

모든 선택 행의 간격은 300초다. 첫 관측을 0초로 둔 기존 경과 시계를 유지하며
UTC 시각이나 다른 설비의 시각으로 옮기지 않는다. 864점 사이의 관측 범위는
258,900초다. 이후의 미관측 끝 구간을 채우거나 결측 행을 삭제하지 않는다.
이 범위의 원 관측 `origin`은 `simulation`이다.

## 점수 변환과 선언 정책

점수는 원 압력 수두 `h`에 다음의 독립 작성한 연구 시나리오를 적용한다.

```text
s = (35 m - h) / (5 m)
score_unit = "1"
trigger = 1
reset = 0
persistence_s = 600
recovery_s = 600
max_gap_s = 300
latch = False
```

35 m 기준과 5 m 척도는 관측 평균·표준편차·분위수에서 추정하지 않았다.
점수를 만든 뒤 경보 수나 성능을 보고 기준을 조정하지 않는다. 현장의
승인된 압력 경보 설정값이나 통계적 학습 결과로 해석하지 않는다. 점수는
확률이 아니며 음수를 자르거나 절댓값으로 바꾸지 않는다.

원 정책의 시작 조건은 `s > 1`이므로 수두가 30 m보다 낮을 때 지속 타이머가
시작된다. `s <= 0`, 곧 수두 35 m 이상일 때 회복 조건을 평가한다.
두 조건 사이에는 원 정책의 히스테리시스가 적용된다. 600초는 호출자가
선언한 지속·회복 시간이며 관측한 탐지 지연이나 실제 전달 지연이 아니다.
경보의 최초 상태는 원 정책이 새로 생성하는 비활성 상태다. 이 구간 앞의
알 수 없는 경보 이력을 추정해 초기 활성 상태로 넣지 않는다.

원 압력 값이 없으면 점수도 `None`이고 `valid=False`다. 유효하지 않은 점수를
0이나 정상 상태로 바꾸지 않는다. 원 정책은 이때 `UNKNOWN`을 반환하면서
기존 활성 메모리는 유지하고 지속·회복 타이머를 초기화한다. `UNKNOWN`은
해당 시점의 경보 판정이 미상이라는 뜻이며 활성 메모리와 별도로 읽어야 한다.

직전 관측과의 차이가 `max_gap_s`를 **초과**할 때 타이머가 다시 시작된다.
정확히 300초인 정상 표본 간격은 공백 초과가 아니다. 장기 공백을 매끈한
연속 이력으로 간주하거나 사이의 경보 상태를 보간하지 않는다.

## 재현과 입출력

저장소 루트에서 기존 모니터링 소스 위치를 전달한다. 핵심 Python 환경 외에
기존 loader용 pandas와 모니터링 프로젝트의 실행 의존성이 필요하다.

```powershell
python scripts/check_alarm_source.py --monitoring PATH_TO_PROCESS_MONITORING
```

원자료 위치를 바꿀 때는 `--root PATH_TO_BATTLEDIM`을 추가한다. 공급자 체크섬과
필수 파일은 그대로 적용된다. 모니터링 프로젝트의 코드는 수정하지 않고,
Python 소스 트리의 실행 전후 SHA-256·파일 수와 원 정책 파일의 SHA-256,
패키지 버전을 남긴다. Git 정보가 없는 소스 복사본은 commit/변경 상태를
미상으로 두고 소스 내용 해시를 비교한다.

입력 계약은 `SignalFrame`의 원 시계·점수·단위 `"1"`·유효성과
`AlarmReplaySpec`의 정책·근거를 연결한다. context의 자산·시계·origin과 점수
출처·정책 근거를 명시한다. `policy_reviewed=False`인 요청은 `needs_data`로
보류하고 원 정책을 생성하지 않는다. 검토한 요청은 `exchange_checked`로
기록된다. 이 상태는 자료·정책 경계의 실행 확인이며 현장 경보 적합 판정은 아니다.

원 정책은 `NORMAL`, `PENDING`, `ALARM`, `UNKNOWN`과 `active`를 반환한다.
봉인 결과에는 정책, context, 공급자 버전·소스 해시, 점수 프레임 해시,
행별 상태와 관측 활성화 기록이 있다. `check_integrity()`로 현재 로컬 결과와
그 결과가 보유한 원 점수 프레임 연결을 확인한다. 공개 JSON만 다시 읽은
객체는 비공개 원 프레임을 복원한 것이 아니다.

`activation_records`는 이 관측 순서에서 비활성이 유효한 `ALARM`으로 바뀐
경우다. 미상 관측 뒤 이미 활성인 경보가 다시 보인 것을 새 경보로 세지 않는다.
관측 활성화 수를 누설 발생 수나 사람에게 경보가 실제 전달된 횟수,
HRA의 연간 요구 빈도로 변환하지 않는다.

원 관측·변환 점수·상태 행·상세 실행 결과는 `artifacts/alarm_source/`에만 쓴다.
[공개 실행 요약](../research/alarm_source_results.json)은 출처·이용 조건·해시,
선언 규칙과 표본·상태·활성화의 집계, 원 API 버전 및 제한을 담는다.
원 관측이나 변환된 수치 행을 배포 코드에 넣지 않는다.

현재 실행은 864점에서 `PENDING` 2점, `ALARM` 862점과 관측 활성화 1건을
남겼다. 원 압력 수두와 선택 유량의 결측·invalid는 각각 0건이고 300초를
초과한 간격도 0건이다. 이 집계는 선언 정책의 출력이며 참 경보·오경보의
수나 첫 구간의 누설 발생을 설명하지 않는다. 처음부터 새 정책으로 재생했기
때문에 이 자료보다 앞의 실제 경보 활성 여부도 입증하지 않는다.

## 합성 확인과 자료 해석의 구분

같은 임계값·지속·회복·최대 공백 조건으로 별도의 작성된 점수 이력을 확인한다.
이 합성 이력은 실제 BattLeDIM의 결측이나 사건을 추가로 관측한 것이 아니다.

- 활성 후 결측: `UNKNOWN`에서도 활성 메모리가 유지되고, 이후 회복 조건이
  새로 누적되어야 비활성화되는지를 확인한다.
- 지속 조건 중 600초 공백: 이전 누적 시간을 이어 붙이지 않고 공백 뒤의
  지속 시간이 채워졌을 때 활성화되는지를 확인한다.
- 별도 `latch=True` 시나리오: 회복 대역의 시간이 충분해도 래치를 유지하며
  작성된 명시적 reset 요청에서 해제되는지를 확인한다. 이 요청은 실제 사람의
  확인·조작 기록이 아니다.

또한 실제 점수 행의 결과를 새로 생성한 같은 원 `AlarmPolicy`의 순차 호출과
대조한다. 이는 어댑터가 원 API의 의미를 바꾸지 않았는지 확인하는 검사다.
독립적인 물리 모델이나 정답 사건으로 성능을 검증한 것처럼 세지 않는다.

## 아직 필요한 근거

이 스크립트는 누설 정답 CSV·수리 보고·발생 설정을 경보 입력이나 평가 정답으로
읽지 않는다. 따라서 첫 864행의 경보 집계로 오경보율·검출률·혼동 행렬을
계산하지 않는다. 임계값을 학습하거나 다른 기간의 holdout 성능을 주장하지도
않는다. 그러한 평가는 독립적인 사건 시작·종료·관측 가능 범위와 사전에 정한
평가 규칙, 설비와 기간 간의 분할 근거가 먼저 필요하다.

사람의 경보 인지·해석·확인·행동·복구 정답과 관찰된 작업 조건도 없다.
경보 활성화를 곧바로 작업자의 실패 사건으로 바꾸거나 점수를 HEP로
사용하지 않는다. 사람 반응을 연결하려면 같은 자산·사건·시계에 대한 전달,
인지, 행동 시각과 완료/실패/관측 중단, 작업 요구조건·인적 수행 요인 및
분야 전이의 검토가 필요하다. 이후 기존 HRA 소유 프로젝트의 방법을 별도로
적용해야 하며 이 자료만으로 모수를 결정하지 않는다.

원 시각은 샘플 좌표다. 경보 장치 생성·통신 전송·표시·확인 시각이 없으므로
실제 전달 지연도 추정하지 않는다. 실제 감지·보호 성능, 경보 설정의 공정
안전 적합성, 운전자 대응과 현장 자격은 이 재생의 완료 범위에 포함되지 않는다.
