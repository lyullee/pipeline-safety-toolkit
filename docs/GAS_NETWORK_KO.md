# 정상 기체 관망 연결과 GasLib 자료

`gas_network`는 기존 lh2dt_models의 SteadyNetwork·Pipe와 CoolProp을 재사용한다.
유체명을 고정한 수소 모델을 복제하지 않고 원 P/h 접점 해법과 물성 호출을
사용한다. 현재 범위는 구간 입구 밀도를 쓰는 저마하 정상 선별 해석이다.
분기·지정 질량 인출·열·역류·병렬과 선언한 동일 조성 혼합물을 연결했다.
전체 기체 관망·사고·독립 실험 검증 완료를 뜻하지 않으며 기술 상태는 partial이다.

## 설치와 실행

기존 장치 프로젝트를 별도로 설치하거나 소스 경로를 지정한다. 원 엔진의
SciPy·CoolProp 의존성도 필요하다. 현재 실제 버전·커밋과 소스 해시는
`research/gas_network_results.json`에 있다. 물성 모델의 글로벌 에너지 기준을
이 어댑터가 바꾸지는 않으므로 외부 코드와 함께 쓸 때 같은 기준을 유지한다.

```powershell
python examples/gas_network.py --lh2dt PATH_TO_LH2DT --output artifacts/gas_network/example.json
python examples/gas_network.py --write-job examples/gas_network.json
python -m pip install -e PATH_TO_LH2DT
pipeline-integrity gas-network examples/gas_network.json --output artifacts/gas_network/result.json
python scripts/check_gas_network.py --lh2dt PATH_TO_LH2DT
```

저장한 JSON에는 specification과 context만 둔다. Python에서는
`solve_gas_network(specification, context)`를 호출한다. GasNetwork와 RunContext는
JSON을 직접 읽을 수 있고 계산 전에 중첩 값까지 다시 검증한다. 선택 엔진이
없으면 ImportError가 명확하게 발생한다. 기본 상태·형상·근거는 예제를 바꿔
사용하며 공개 예제의 수치를 실제 공정 기본값으로 간주하지 않는다.

## 입력과 교체 경계

| 객체 | 입력과 의미 |
|---|---|
| GasBoundary | ID, 고정 절대압 Pa·온도 K, 고도 m |
| GasJunction | ID, 초기 절대압·온도 추정, 지정 인출 kg/s, 고도 m |
| GasPipe | ID·양 끝 노드, 길이·내경·거칠기 m, 국부 손실, 유체로 들어오는 열 W, 구간 수 |
| GasNetwork | 유체·백엔드·물성 기준, 근거 ID, 노드·관, 수치 예산과 잔차·적용 영역 기준 |
| GasNetworkResult | 문맥·원 사양 해시, 원 결과·소스 해시·최종 물성·수지·상태·receipt |

고정 경계의 온도는 해당 경계에서 들어오는 유체 상태다. 관에서 그 경계로
나가는 유체의 온도가 항상 같다는 뜻은 아니다. 따라서 하류 물성은 각 관이
실제 전달한 엔탈피와 수신 압력으로 별도 계산한다. 접점의 혼합 상태와 각
관의 도착 상태를 구분한다. 모든 계산 노드는 같은 유체 조성을 사용한다.
서로 다른 조성을 혼합하거나 미지의 가스를 메탄으로 바꾸는 모델은 없다.

지원 백엔드 표기는 HEOS·PR·SRK다. 실제 P/T·P/h·수송 물성·음속 지원은
해당 설치와 유체에 달려 있다. 현재 검증은 HEOS를 사용했다. 지원되지 않는
플래시나 물성은 보류하며 백엔드를 바꿔 맞추지 않는다. 강제 상 지정이나
임의 이성분 상호작용 추정을 추가하지 않았다. 물성 의미는
[CoolProp 공식 인터페이스](https://coolprop.org/coolprop/HighLevelAPI.html)를 따른다.

예산 기본값은 노드 128개·전체 관 구간 256개·원 엔진 상태 변환 20000회,
엔탈피 반복 50회·각 압력 해석의 평가 200회다. 사용자가 지정 범위에서
바꿀 수 있다. 상태 변환 계수는 P/T·P/h 캐시 미스이며 개별 EOS 함수 호출
수나 시간 제한은 아니다. 최종 노드·도착 상태의 추가 물성 조회는 노드와
구간 수로 제한된다. 많은 병렬 관도 구간 예산에 포함한다.

## 인출 포트와 수지

질량 인출은 접점에서 지정한 질량·그 접점 엔탈피가 나가는 경계 조건이다.
유량을 만들어 내는 소비 장치나 제어기의 성능 예측이 아니다. 기존 원 해법에
직접적인 노드 부하 입력이 없어 계산용 말단과 일정 질량 포트로 표현했다.
그 말단의 상태는 수요 장치의 실제 압력·온도가 아니며 최종 물리 노드
목록에서 제외한다. 원 전체 응답에는 남기고 withdrawal_links로 대응시킨다.
소비 장치가 실제로 지정 인출을 유지할 수 있는지는 별도 근거가 필요하다.

원 해석의 optimizer·엔탈피 반복·접점 보존 판정을 모두 확인한다. 그와 별도로
전체 링크의 부호 있는 질량·전달 엔탈피로 접점 및 전체 수지를 재계산한다.
이때 한 경계의 h_ref를 빼 에너지 잔차가 임의의 엔탈피 기준 오프셋에 의존하지
않도록 한다. 질량 수지도 따로 통과해야 한다. 열은 선언한 관 열의 합이다.
원 장치 결과·물성·실제 입력을 보존하며 결과를 고쳐 닫힘을 만들지 않는다.

저장량 0의 접점에 수치적으로 해소된 유입이 없으면 온도·엔탈피가 정해지지
않는다. 잔차와 원 성공 플래그가 맞아도 이런 노드는 별도로 표시하고 전체
결과를 withheld로 둔다. 초기 추정 온도를 물리 해로 승인하지 않는다. 실제
정체 사례와 기원·수지·중첩 변경 등의 정책 검사를 함께 실행했다.

에너지 판정의 의미는 정적 엔탈피 이송과 지정 열이다. 운동 에너지 변화와
위치 에너지까지 닫힌 전체 장부가 아니다. 서로 다른 끝점 고도는 현재
out_of_scope로 반환한다. 원 관의 중력 운동량과 엔탈피 사이의 완전한 결합은
PI-X01의 확장 과제다. 고도를 조용히 0으로 바꿔 실행하지 않는다.

수지의 기본 절대 허용값은 1e-8 kg/s·0.01 W·관 운동량 0.01 Pa이며 상대
판정도 함께 제공한다. 작은 유량에는 더 엄격한 절대값이 필요하다. 작은
절대 잔차만으로 상대 정확도를 주장하지 않는다. 원 해법의 차원이 있는
기울기 정지 조건 때문에 더 엄격한 요청이 보류될 수 있고, 외부 엔진의
스케일된 잔차 API를 PI-X01로 요청한다. 허용값을 크게 해 완료로 바꾸지 않는다.

## 구간 분할과 적용 범위

한 관을 같은 길이 구간으로 나누고 각 구간에 원 Pipe를 연결한다. 국부 손실과
열도 전체 합이 바뀌지 않게 나눈다. 내부 노드는 초기 P/h의 보간을 수치
초기값으로만 사용하고 최종 상태는 원 접점 해법으로 푼다. 구간 입구 밀도
근사를 압축성 운동량 적분이나 고마하 해법으로 표시하지 않는다.

각 구간의 실제 상류·도착 상태에서 마하수·밀도 변화·압력 변화와 원 운동량
잔차를 검사한다. 기본 최대 마하수는 0.1, 밀도·압력의 상대 변화는 각각
0.05다. 이 값들은 해석 영역을 제한하는 선언 기준이며 실제 오차 상한이나
실험 검증을 뜻하지 않는다. 초과 시 원 계산을 보존하고 out_of_scope다.
열이 있으나 대류 질량 이송이 해소되지 않은 경우도 적용 범위 밖이다.

결과는 computed·withheld·out_of_scope를 구별한다. result_origin은 입력 기원이
measured여도 simulation이다. check_integrity()로 receipt의 중첩 변경을 확인한다.
receipt는 진위·공정 안전·현장 적합성의 인증이 아니다.

`checks.pipe_flow_summary`는 각 원 pipe ID에 대해 선언된 start→end 방향 기준의 부호 있는 질량유량(kg/s), 방향, 원 node ID, native segment link ID와 인접 분할 간 최대 유량 편차를 제공한다. native segment의 left/right 방향이 원 관 방향과 달라도 각 link 유량 부호를 선언 start→end 방향으로 먼저 정규화한다. 연결 endpoint가 선언 chain과 맞지 않으면 계약 위반으로 거부한다. 분할 간 질량 연속성이 지정 절대/상대 허용값을 벗어나면 요약 유량을 null 및 `unresolved`로 표시하고 결과는 withheld가 된다. 원 엔진 세부 결과는 `native`에 그대로 보존한다. 이 요약은 downstream 연동용 교환 계약이며 별도 유동 계산은 하지 않는다.

## 실제 기준 사례

실제 엔진으로 메탄·질소 인출, 500 W 가열, 서로 다른 두 공급 온도의 혼합,
역류·병렬, 영역 초과·액체 거부·예산 보류를 실행했다. 선언한 메탄 0.9·수소
0.1 몰분율 문자열도 현재 설치에서 P/h 계산과 도착 물성 조회까지 통과했다.
이 사례의 성공을 임의 혼합물·조성 변화에 일반화하지 않는다. 전체 16개
사례와 별도 CLI, 원 소스·물성 버전은 gas_network_results를 따른다.

질소 101/100 kPa·300 K, 길이 4000 m·내경 0.04 m의 저속 층류를 비교했다.
중간 상태의 p/rho·점도를 일정하게 둔 등온 층류 기준에서 질량 유량은
πD^4(p_in²-p_out²)/(256 μ(p/rho)L)이다. 실제 유동은 P/h 기반이며 이 비교는
낮은 압력차의 수치 기준이다. 구간 1·4·8개의 기준 대비 차이는 각각 약
0.497%·0.125%·0.063%로 줄었다. 실제 Reynolds 수가 층류 범위임도 확인했다.
같은 EOS를 사용한 이 비교는 독립 기체 실험 정확도의 검증이 아니다.

## GasLib 자료와 미완료 매핑

[GasLib 공식 시험 자료](https://gaslib.zib.de/testData.html)의 버전
GasLib-11-v1-20211130 ZIP 7022바이트를 취득했다. 원 .net/.scn의 CC BY 3.0
표시와 요청된 인용을 보존했다. Schmidt 등의 2017년 논문 DOI
10.3390/data2040040과 Pfetsch 등의 ZIB Report 12-41(2012)을 인용한다.
저자·기관·권리 URL·원 해시는 데이터 카탈로그와 연구 기록에 있다.

원 자료는 공급 3·수요 3·내부 5개 노드, 관 8개·밸브 1개·압축기 2개다.
공급자가 실측 관망이 아닌 시험 자료로 분류한 자료다. .net은 형상·경계를,
.scn은 정상 운전의 지정을 담는다. 시계열 관측이나 사고 빈도가 아니다.
XML의 그림 좌표를 관 길이로 사용하지 않는다. m/km/mm를 명시적으로
변환하고 원 유량·압력·물성 단위와 경계를 보존한다. 단위가 모르면 거부한다.
DTD·entity를 실행하거나 원 XSD를 외부에서 자동 취득하지 않는다.

read_gaslib는 원 조성·압력 기준·지정 유량의 기준과 질량 변환·열 경계·압축기
구성과 밸브 상태를 추정하지 않는다. 전체 원 사례는 needs_data다. 별도 실행은
한 관의 형상만 가져와 순수 메탄·300 K·절대압 6/5.5 MPa·단열이라는 조건을
명시한 사례다. 원 열전달 계수를 그대로 적용한 것이 아니며 원 지정 운전과
다른 장치들을 계산하지 않았다. 원 GasLib 해의 재현·검증으로 집계하지 않는다.

최초 Python 다운로드는 TLS 인증서 체인 검증에 실패했다. 검증을 끄지 않고
Windows 기본 인증서 검증을 쓰는 Invoke-WebRequest로 취득한 뒤 ZIP·SHA-256을
확인했다. 이 해시는 출판사 체크섬이 아니라 이전 취득 해시다. 같은 문제가
있으면 동일 URL의 파일을 기본 HTTPS로 data/raw/gaslib11에 받은 뒤 취득
스크립트의 고정 해시 검증을 실행한다. 실패 원장도 로컬에 보존한다.

## 남은 연구

원 엔진의 전체 에너지·고도·스케일된 잔차·직접 노드 부하 계약, 일반 능동
장치와 기체 조성 매핑, 원 자료의 열·유량·경계 조건, 독립 실험 비교가 남아
있다. 실측 온도·압력의 단위와 기준이 맞는 자료를 확보한 뒤 적용성을 검토한다.
고마하·비정상·상변화·누설·압축기 제어를 이 선별 해석의 완료 범위로 세지 않는다.
