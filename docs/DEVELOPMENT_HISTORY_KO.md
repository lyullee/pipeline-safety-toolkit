# 개발 과정과 검증 의사결정 기록

이 문서는 공개0.1.0a1까지의 개발 흐름과 이후 재개에 필요한 결정을 설명한다. 실제 코드의 기준은 커밋·버전과 `src/`, 실제 검증의 기준은 실행 receipt와 시험 소스다. 이전 기록은 [STATUS](STATUS_KO.md), [PLAN](PLAN_KO.md), [CONTINUATION](CONTINUATION_KO.md)에 보존되어 있다. 역사 기록의 분모·환경·결과를 현재 값으로 소급해 덮어쓰지 않는다.

## 1. 목표와 범위의 정리

초기 목표는 배관 공학 계산을 파라미터와 사용자 데이터로 재사용할 수 있는 Python 모듈로 만들고, 이미 존재하는 재료·감시·인적 신뢰도·위험 엔진과 연결하는 것이었다. FTA는 연결의 예시이며 유일한 평가 방법이 아니다.

구현이 확장되면서 기본 레지스트리, adapter, 외부 엔진 기능과 개별 공학 방법의 개수가 섞여 진행률 해석에 혼선이 있었다. 따라서 공개 기준을 **고정223개 공학 방법**으로 정하고 구현·변형·API·독립 물리시험·실측 적합성을 각각 다른 집계로 관리한다. 174/202 등의 예전 목록은 해당 기록의 범위에서만 읽는다.

다른 GitHub 프로젝트는 필요한 API와 의미 보존을 확인하는 연동 대상이다. 그 프로젝트의 모든 물리 모델을 이 패키지의 자격 검증 대상으로 추가하지 않는다. 중복 기능은 기존 소유 함수를 호출하고 새 구현 수로 중복 집계하지 않는다.

## 2. 공통 계약과 패키지 구조

각 모델을 독립 request, context, provider, 결과 계약으로 분리했다. 기본 레지스트리는 작은 계산을 실행하고, 공학 방법 카탈로그는 기존 typed 함수의 연결점을 제공한다. 하나의 범용 딕셔너리로 모든 물리 입력을 강제하지 않는다.

SI 단위, absolute/gauge 압력, 기준 체적, 시계와 지연, 설비·위치·자료 출처를 계약에 포함했다. 알려지지 않은 값은 알려지지 않은 상태로 보존한다. signed 유량·하중·열유속을 유지하고, 해석 불가능한 조건을0으로 치환하지 않는다.

원 관측과 실행 환경은 코드 배포에서 분리했다. `data/raw`, `data/processed`, `artifacts`, 가상환경과 개인 분석 경로를 Git 및 소스 배포에서 제외한다. 외부 소유 코드와 데이터는 별도 라이선스·버전·실제 import 경로를 확인한다.

## 3. 구현 확장과 통합

- 유동·장치: 액체/가스 손실, 상사·운전점, 밸브·노즐, 압축·재순환, 용기와 관 재고를 구성했다.
- 과도·수송: 보존형 가스장, 액체 압력파, 자유수면·혼합 충수, 분산과 사건 경계를 분리했다.
- 열·구조: 열역학 공급자, 정상/과도 열, 열팽창·압력 하중, 프레임·좌굴과 국부 관측 좌표를 연결했다.
- 재료: 소유 재료 엔진을 통해 압력 단면, 피로·크리프·균열 성장, 전기화학 의미와 보호 전하를 교환했다.
- 운영·계측: 교정·총량·불확실성, 시계, 데이터 reader, 제어·인적 반응·감시와 위험·비용 경계를 확장했다.

한 방법에 여러 가지 용도가 있을 때 실제 API와 지원 영역을 선언하고 소스 바이트를 고정했다. 현재223개 방법,339개 변형 매핑,304개 API가 있다. 이 매핑의 완성을 경험계수의 보정이나 독립 실측 검증으로 해석하지 않는다.

## 4. 공개 자료와 소유권 경계

공개 자료는 파일의 존재만으로 검증 근거가 되지 않는다. geometry, 물성, 단위, 계측 위치, 시각과 라이선스를 확인해야 한다. 실험 자료의 조건이 부족하면 임의의 물성을 넣어 실측 검증으로 표시하지 않았다. 자료 후보와 실제 확보·reader·교정·독립 비교 상태를 구분했다.

대용량 원본은 코드를 배포하는 저장소에 넣지 않았다. 공개 데이터의 출처와 별도 이용조건은 보존하며, 제한이 있는 자료는 public fixture나 계수 도출에 자동 사용하지 않는다. 최근 남은 물리시험 자료 검토는 `research/physical_independent_data_screen.json`에 기록되어 있다.

## 5. 입력·계산식·수치 범위·연결 검증

사용자 요청에 따라 입력검사, 손계산/독립 기준, 극단값, 모듈 연결, 기존 기능 재확인, 전체 계산을 구분해 수행했다. 모델별 representative 캠페인은16,795건이며, 연결226건·기존 기준 재실행16,346건·전체 계산223건으로 구성된다.

이 캠페인의 통과를 독립 물리 자격률로 합산하지 않았다. 공개 설치 시험도 별도의17개 파일276건 부분집합으로 선언했다. 외부 소유 프로젝트나 원 관측이 필요한 연구 시험 전체를 깨끗한 설치의 기본 시험이라고 표현하지 않는다.

## 6. 원격과 로컬 실행의 전환

초기에는 승인된 슈퍼컴 배치와 환경·JUnit·로그·체크섬을 이용했다. 연결과 환경 누락을 코드 실패와 구분했다. 이후 로컬 병렬 시험이 승인되어4개 프로세스와 고정 의존 소스로 독립 물리 기준을 실행했다. 이 저장소의 원격 템플릿은 인증 정보를 포함하지 않으며 새 clone에서 자동으로 원격 인증을 시도하지 않는다.

독립 작업을 묶고 이전 통과 증거를 재사용해 반복 시간을 줄였다. 재사용에는 생산 소스, 해당 시험, Python/패키지 환경, 원 receipt와 JUnit·로그 해시의 일치가 필요하다. 코드나 조건이 달라진 경우 결과를 새 소스에 그대로 붙이지 않는다.

## 8. 실패에서 확인한 구체적인 내용

### 소스가 실행 중 변경된 경우

별도 재료 프로젝트의 파일이 바뀐 배치는 시험 계산이 통과했어도 source gate로 집계를 보류했다. 그 소스를 고정한 복사본으로 다시 실행했다. 한글 경로 전달 중의 module import 오류는 환경 문제로 분류하고 Python 안에서 경로를 전달해 해결했다.

### 양극 수명

보호 전하 예산의 소유 함수 시험만으로 새 수명 API를 검증하지 않았다. 공개 `evaluate_anode_lifetime`을 직접 호출하고 독립 전류 적분과 최초 용량 교차 root로 고갈 시간을 비교했다. 소비 전하와 부족/잔여 전하의 수지를 함께 확인했다. 보호 전위와 부식률을 전하 예산에서 추정하지 않았다.

### 큐빅 상태식

원시 PR/SRK 압력–체적 식의 독립 수치 root와 실제 공급자를 비교했다. 특정 PR 질소2MPa350K의 자동P–T 밀도 검색은 실패했다. 같은 backend의 T–밀도 입력으로 압력을 회복하는 것은 확인했지만 원래P–T 한계가 수정됐다고 표현하지 않았다. 이 사항은 `research/physical_backend_limits.json`에 보존한다.

### 탱크 호흡

이상기체 재고 손실 기준과 온도 구간별 호흡 관측을 비교했다. 초기40개 구간에서 정한 오차 기준을 만족하지 못한 시험은80개 구간으로 세분화했다. 수렴 방향을 확인했고 허용오차와 계산 코드를 바꾸지 않았다.

### 기존 실측 실패

관마찰2건, 속도별 강도1건, 크리프 수명1건의 기존 실측 실패는 유지했다. 이미 들여다본 비교 구간에 대한 탐색 보정은 새 독립 검증으로 재명명하지 않았다. 구간별 유효 계수가 실제 거칠기나 원인 식별을 뜻하지 않는다는 점을 기록했다.

## 9. 공개 준비와 발견 사항

기본 import에서 선택 SciPy를 요구하던 펌프/회전축 경계를 실제 계산 시점으로 옮겼다. 깨끗한 core 환경에서 선택 라이브러리가 없는 설치, 기본 실행과223개 바인딩을 확인했다. 새 이름 `pipeline-safety-toolkit`를 배포명으로 사용하되 `pipeline_integrity` import와 기존 CLI를 유지한다.

원자료/캐시/개인 환경, 계정·인증 정보와 비공개 문서를 archive에서 제외한다. 원 소스와 wheel/sdist의 바이트 일치, 출처 고지, 정적 오류 검사와 공개 부분집합을 점검한다. 전체 스타일 경고는 별도의 기술 부채로 표시하고0경고라고 주장하지 않는다.

## 10. 이후 연구를 이어가는 기준

남은25개는 독립 기준이나 자료가 더 필요하다. [우선순위](PHYSICAL_VERIFICATION_BACKLOG_KO.md)와 [재개 절차](RESEARCH_CONTINUATION_KO.md)를 따른다. 새 조건의 자료를 확보한 뒤 기준과 허용오차를 고정하고, 이미 관찰한 결과에 맞춰 기준을 바꾸지 않는다. 배포 버전 변경은 물리 자격의 자동 갱신이 아니다.
