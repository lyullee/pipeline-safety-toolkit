# 물리 모델의 파라미터 보정

이 모듈은 관측과 전방 모델의 차이에서 범위가 정해진 파라미터를 추정한다.
실제 물리 계산은 호출자가 제공하는 함수나 `WaterForward`가 수행한다. 최적화는
SciPy의 경계가 있는 least_squares를 사용한다. 새 수력·모니터링·HRA 엔진을
중복 구현하지 않는다.

## 실행 가능한 예제

```powershell
pipeline-integrity water-fit examples/water_calibration.json --output artifacts/fit.json
python scripts/check_calibration.py --root data/raw/battledim
```

engineering과 water 추가 의존성이 필요하다. 첫 명령은 자체 작성 관의 알려진
수요 배율 1.12·거칠기 배율 0.93을 추정하는 합성 예제다. 두 번째 명령은 별도
취득한 공개 데이터로 실제 보정·시간 분리 비교를 수행한다. 원자료나 변환한
관측 행을 공개 패키지에 넣지 않는다.

JSON 작업에는 `network`, `specification`, `sensors`, `bindings`, `observations`,
`fit`, `context`를 모두 명시한다. INP 경로는 작업 파일 디렉터리를 기준으로
해석한다. 저장한 관측은 `Observations` 계약이고, CLI가 임의 코드를 실행하거나
자료를 자동 다운로드하지 않는다. 원본 INP를 수정하거나 보정값을 기본 모델에
자동 적용하지 않는다.

## 공통 Python 계약

| 계약·함수 | 역할 |
|---|---|
| FitParameter | 파라미터 ID·단위·하한·상한·초기값 |
| ResidualScale | 잔차를 나눌 양의 척도·단위·설정 출처 |
| Observations, ObservedChannel | 자산·시계·생성 방식·출처 해시·시각·관측·valid |
| observations_from_frames | 기존 SignalFrame의 선택 채널을 관측 계약으로 변환 |
| FitRequest | 공급자 ID·버전·시간 분리·손실 함수·차분 폭·수치 예산 |
| Prediction | 전방 계산 상태·자산·시계·단위·시계열·공급자/실행 해시 |
| fit_parameters | 학습 구간 추정, 국소 식별성, 이후 구간의 전후 오차 |

`fit_parameters(observations, request, context, predict)`에서 predict의 서명은
`predict(parameter_values, requested_time_s, context) -> Prediction`이다.
predict에는 관측값이나 검증 정답을 넘기지 않는다. 공급자는 요청된 시각에
맞는 값을 동일 자산·시계·단위로 반환한다. 보간이나 시계 자동 이동은 하지
않는다. 공급자가 `parameter_units`를 제공하면 입력 파라미터 ID·단위도 대조한다.
이 속성이 없는 사용자 함수의 파라미터 의미는 호출자가 확인해야 한다.

원자료 해시와 관측 전체의 내용 해시를 따로 보존한다. 공급자 출처 해시는
실행 중 일정해야 한다. 공급자 실행 해시는 공급자가 생성하며 이 모듈은
호출 입력·시각·결과 상태와 함께 기록한다. 최종 결과에는 별도 내용 해시를
추가한다. 이것이 외부 데이터나 공급자 구현의 진실성을 인증하는 것은 아니다.

각 채널의 잔차는 `(예측−관측)/residual_scale`이다. 척도는 단위가 다른 채널의
영향을 조절한다. 사용자가 명시적으로 그런 근거를 주지 않았다면 측정 표준
편차·오차 한계·확률로 해석하지 않는다. 센서 수나 표본 수에 따라 목적함수의
기여가 달라진다. 결과는 채널별 원 단위 RMSE·MAE·편향도 함께 반환한다.

invalid 표본과 None은 목적함수에서 제외하지만 시간축을 압축하지 않는다.
각 채널에 학습·검증의 유효 표본이 모두 필요하다. 전방 예측의 선택 값이
없거나 보류 상태면 추정을 중단한다. 가짜 큰 잔차나 정상값을 넣어 최적화를
계속하지 않는다.

## 학습과 검증

학습은 `time_s <= fit_end_s`, 검증은 `validation_start_s <= time_s <=
validation_end_s`다. 검증 시작은 학습 끝보다 커야 한다. 그 사이와 범위 밖의
관측은 사용하지 않고 수를 기록한다. 검증 관측은 최적화 잔차와 Jacobian에
들어가지 않으며 파라미터 선택 후 두 번의 전방 실행으로 비교한다.

전방 동역학은 요청된 검증 시점까지 초기 상태에서 다시 계산할 수 있다.
검증을 별개의 초기화 상태로 자동 재시작하지 않는다. 초기 조건·미래 운전
패턴의 이용 가능성과 관측에서 파생한 경계의 누출 여부는 사용자가 검토해야
한다. 동일 공개 생성 모델을 공유한 시간 분리는 독립 현장 검증이 아니다.

`fitted`는 최적화의 종료와 국소 식별성 판정이다. 검증 오차 감소나 물리적
정답을 보증하지 않는다. 채택 기준을 따로 정하고 검증 전후 오차를 확인한다.
검증 결과를 본 뒤 모델이나 척도를 바꿨다면 그 구간은 이후 연구에서 모델
선택에 사용한 자료로 취급하고 새로운 평가 구간을 확보한다.

## 수치 방법과 자원

유한한 파라미터 범위를 [0,1]로 정규화한 좌표에서 추정한다. 기본 손실은
linear이며 soft_l1과 huber를 선택할 수 있다. 손실 척도도 무차원 잔차에
적용한다. 강건 손실의 선택이 자동 이상치 분류나 검출확률을 주지는 않는다.

Jacobian은 명시된 구간 비율의 양쪽 차분을 사용하며 경계에서는 실제 가능한
차분 폭을 사용한다. EPANET의 float32 보고값보다 너무 작은 기본 차분을
사용하지 않도록 폭을 요청에 명시했다. 현재 기본 비율은 0.005다. 비선형·
불연속 제어에서는 차분 폭과 시작값에 대한 별도 민감도 검토가 필요하다.

차분·최종 식별성·검증까지 실제 공급자 호출을 모두
`maximum_model_evaluations`에 센다. 동일 파라미터와 요청 시각은 캐시를
재사용한다. SciPy의 nfev는 이 실제 호출 수와 다르다. 별도의
`maximum_optimizer_evaluations`도 있으며, 한도 소진으로 중단하면 추정값을
완성된 결과로 반환하지 않는다. 동작 시간의 강제 제한은 호출 프로세스에서
관리해야 한다.

마지막의 원 잔차 Jacobian에 SVD를 적용한다. 정규화 좌표에서 상대 특이값
기준으로 rank와 조건수를 반환한다. rank 부족은 `unidentifiable`, 최적화
미종료는 `not_converged`, 공급자 보류는 `withheld`, 실제 호출 예산 소진은
`budget_exhausted`다. 경계에 붙은 파라미터도 표시한다. 이 진단은 국소적이며
전역 유일성·모델 형태의 정확성·신뢰구간·공동 확률분포를 계산하지 않는다.

## 물 관망 공급자

`WaterForward`는 매 실행에서 원본 INP를 새로 읽고 다음 결합을 메모리에만
적용한다. 파라미터가 같은 속성을 중복 수정하거나 요소 유형이 틀리면 거부한다.

| kind | 단위 | 적용 대상 |
|---|---|---|
| demand_multiplier | 1 | 원래 전역 수요 배율에 추가 곱 |
| junction_demand_multiplier | 1 | 지정 접점의 모든 수요 계열에 곱 |
| pipe_roughness_multiplier | 1 | 지정 관의 원래 거칠기에 곱 |
| emitter_coefficient | m³/s/m^0.5 | 접점의 q=C√h 계수 지정; h는 수두 m |
| reservoir_head_offset | m | 지정 저수지 기준 수두에 더함 |
| initial_tank_level_offset | m | 탱크 바닥 위 초기 액위에 더함 |

양의 배율, 음이 아닌 emitter 계수, 탱크 최소/최대 액위와 제곱근 emitter
지수를 검사한다. emitter의 위치는 이미 선택된 접점이다. 이것만으로 배관
내 누설 위치를 역추정했다고 표시하지 않는다. 대상 관의 마찰식과 기존
거칠기 단위는 원 관망을 따른다.

`WaterSensor`는 채널·요소·수량·유량 부호를 명시한다. pressure_head는 접점
수두 m, water_level은 탱크 바닥 위 액위 m, volume_flow는 원 링크 방향의
m³/s다. `flow_sign=-1`로 선언한 유량만 반전한다. 센서 이름의 유사성으로
요소를 추정하지 않는다. `start_time_s`는 Python 공급자의 상위 시계 오프셋이며
기본 0이다. 요청 시각은 선언한 보고 격자에 정확히 있어야 한다.

수력 실행은 공통 epanet.py를 사용한다. L/s 직렬화에서 WNTR의 원시 FLOWCHANGE
옵션을 SI로부터 변환하고, 파일 파서의 상대 정확도 제한을 공개 C API의
setoption으로 요청값에 맞춘다. getoption으로 읽은 실제 적용값을 SI로
변환해 요청과 대조한다. 기본 1e-8을 파일에 썼다는 사실만으로 적용됐다고
표시하지 않는다. 수렴 경고·원 엔진 오차·접점 수지는 계속 판정한다.

## 공개 SCADA 실행 결과

`check_calibration.py`는 2018년의 첫 576개 5분 보고를 읽고 여섯 번째마다
선택했다. 총 96시점·37센서이며 평균·보간을 하지 않는다. 첫날의 48시점으로
추정하고 다음 날의 48시점으로 비교했다. 누설 정답과 숨겨진 생성 관망은
입력에 사용하지 않았다.

수요·전체 관 거칠기의 배율을 0.9~1.1에 제한하고 초기값은 1이다. 잔차
척도는 압력 1m·유량 0.001m³/s·액위 0.1m로 선언한 가중치다. 수력은 상대
정확도 1e-6·수두 오차 1e-5m·유량 변화 1e-8m³/s로 별도 명시하고 모든 실행의
실제 적용값·경고·수렴을 확인했다. 이 조건은 수질 기준 사례의 엄격한 요청과
별도 실행이며 기존 경고를 지우거나 그 결과를 덮어쓰지 않는다.

51회 전방 호출 후 수요 배율 약 0.99280·거칠기 배율 약 1.00445를 얻었다.
국소 rank는 2, 정규화 Jacobian 조건수는 약 71.1이다.

| 무차원 RMSE | 초기 | 보정 후 |
|---|---:|---:|
| 학습 | 0.89262 | 0.86724 |
| 다음 날 검증 | 1.35281 | 1.36891 |

학습은 약 2.8% 개선됐지만 다음 날은 약 1.2% 악화됐다. 이 배율을 기본 모델에
자동 적용하지 않았다. 이 결과는 고정된 두 배율의 시간 일반화 한계를 보여준다.
후속 연구에서 계절·시간별 수요·초기 재고·관망 형태 차이를 검토할 때 새로운
평가 구간을 분리해야 한다. 원 단위 채널별 수치는 실행 요약에 있으며 수치
적합도가 누설 정답이나 센서 정확도를 입증하지 않는다.

현재 0.1.0.dev0의 구현·소프트웨어·합성 기준 검증과 공개 자료 적용은
`network.calibration`의 범위다. 누설 위치 후보 검색, 다중 시작값의 전역
탐색, 불확실성 추정은 다른 후속 항목으로 유지한다.
