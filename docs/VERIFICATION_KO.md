2026-10-28 사용자 지시에 따라 새 수치 시험·회귀·벤치마크는 누리온으로 이관한다.
아래의 전체 2,403개 통과 기록은 이전 배포 스냅샷에 해당한다. 현재 변경 전체에
적용하지 않는다. 새 구현과 시험 코드는 `research/validation_queue.json`에 등록하고

새 HPC 제어기는 소스 변경·누락 rank·중복 사례와 실제 JUnit 결과를 검사하도록
작성했다. JUnit 합계가 0실패여도 내부 failure/error/skipped 요소가 있으면 거부한다.
관련 시험은 작성했으나 실행하지 않았다. [누리온 절차](NURION_VALIDATION_KO.md)를 따른다.

# 검증 범위와 실행 기록

2026년 10월 28일(KST), Windows/Python3.12에서 **2,403개 검사 통과·실패0·생략0**을
확인했다. 실제 JUnit suite 394.540초다. 집계는 `research/verification_results.json`,
직접 의존성은 `research/tested_environment.json`, 원 JUnit/로그는 배포 밖의
`artifacts/verification/tests.xml`과 `thermal_lifting_full_tests.log`에 있다.

이 실행은 소프트웨어/수치 기준의 전체 회귀이며 모든 기술·현장·규제 자격의
완료가 아니다. FiPy의 기존 upstream DeprecationWarning 두 건은 원 로그에 남긴다.
새 FEM 경로의 deprecated DiscreteField.value 접근은 실제 지원 API로 수정했다.

## 수학·물리 검사

액체 층류의 손실을 독립적인 Poiseuille 해와 비교한다. 역류에서 마찰 압력차가
반전되고 소산이 음수가 되지 않는지, 유량 0에서 정수압이 남는지 확인한다.
난류 계수는 Colebrook 방정식의 잔차를 확인한다. 전이 유동은 기본 보류와
명시적 정책 선택을 따로 검사한다.

탄성 관 파속은 관벽 강체 극한에 접근하고 유연 관에서 낮아지는지 확인한다.
압축기는 등엔트로피 기준과 실제 엔탈피 증가·축동력의 관계를 검사하고 액체
입력을 거부한다. 재고는 실제/기준 상태에서 같은 질량을 보존하는지 확인한다.
CoolProp의 물 300 K 상태와 포화 온도, 2상 단상 계산 차단을 확인한다.

층류 상수 벽온도 Nu=3.66, 대류 적용 영역, 열전도도 0의 냉각 극한, 할인율
0의 현금 흐름, 펌프→에너지 작업 흐름의 전력·시간 환산을 검사한다. 전체
등록 모델에는 실행 가능한 예제 입력이 있어야 한다. 예제의 성공만으로
정확성을 입증하지 않으며 기준식 검사와 구분한다.

절차 증거 누락·선행 작업 차단을 확인한다. 외부 클래스를 실제 호출한 기록은
`research/integration_results.json`에 별도로 남긴다.

## 발견한 실패와 수정

1. 초기 에너지 기준값에서 g=9.81과 기본 9.80665를 혼합했다. 기준값을 같은
   중력 정의로 수정했다. 허용오차를 넓혀 통과시키지 않았다.
2. 전체 모듈을 함께 import하면 `registry` 함수와 같은 이름의 내부 모듈이
   충돌했다. 공개 생성 함수를 `create_registry`로 변경하고 import 순서 검사를
   추가했다. 전체 검사에서 확인한 문제이며 개별 실행만으로는 드러나지 않았다.
3. Mat 다층 열전달 입력의 리스트·튜플 계약 차이를 발견해 실제 소유 계약에
   맞는 리스트로 전달했다. Mat 원본 코드는 수정하지 않았다.
4. BattLeDIM 명목 관망의 기본 솔버 실행에서 최대 접점 수지 잔차가
   3.707697615×10⁻⁴ m³/s여서 보류했다. 수렴 정확도·수두·유량 변화 허용오차를
   명시하고 반복 한도를 설정한 뒤 약 2.62×10⁻⁸ m³/s를 확인했다. 이후 공통
   원 엔진 진단을 추가하면서 이 수지 통과가 수력 수렴을 입증하지 않음을
   확인했다. 반복 초과 경고가 있어 현재 판정은 withheld다. 기존 computed
   판정을 정정했으며 수지 기준 10⁻⁶ m³/s나 경고 기준을 완화하지 않았다.
5. 생성 압축 응답이 지연되는 자료 취득을 중단한 뒤 별도 다운로드 프로세스의
   최대 실행시간을 도입했다. 취득 실패·403을 자료 확보로 표시하지 않았다.

## 추가한 압력파·곡선·공간 재고 검사

단상 특성선법은 단일 관의 압력파 상승/반사 하강 32.458575 m를 기준식과
비교했다. 0.025→0.0125초로 세분한 시간 격자에서 같은 시각의 해가 일치했다.
해당 기준 사례의 최대 체적 잔차는 약 6.94×10⁻¹⁸ m³였다. 분기에서는 동일
임피던스 세 관 접점의 첫 투과파 2/3 계수와 접점 유량을 검사했다. 이 수치는
선형·마찰 없는 기준 문제이며 임의 실제 관망에서 동일 오차를 보장하지 않는다.

정·역류의 Darcy 초기 평형, 대기 방출의 비선형 경계, 증기압·Mach·선형 변형
한계의 보류도 검사했다. 펌프 운전점은 해석 가능한 직선 펌프/제곱 계통 곡선,
직렬·병렬 스케일과 동력 수지를 비교했다. 공간 재고는 동일 상태의 체적 분할
불변성과 `U = m*h - P*V`를 확인했다. 실제 수소 장치·PRISM 포트 결과는 별도
연동 기록에 있으며 그 실행을 확산·피해·빈도 검증으로 확대하지 않는다.

## 장치 팩토리와 적분 연계 검사

기존 장치 팩토리 연계에서는 관의 양방향 상태 입력, 누락 파라미터, 다른 자산·
시계의 상태 차단을 검사했다. 실제 액체/2상 평형과 압력 변화 응답도 호출했다.
최초 1→2 시간 분할의 질량 일치가 10⁻⁷ 상대 기준을 넘었고, 8분할에서 선언한
질량·에너지·벽온도 기준을 만족했다. 허용오차와 각 비교값은 장치 팩토리 실행
기록에 있다. 독립 실험 검증 또는 완전한 다상 파 전파 검증으로 확대하지 않는다.

소유 팩토리에 모르는 필드를 추가했을 때도 ready인 사례를 재현했다. 래퍼의
기본 정책은 이 필드를 거부한다. 시간 세분화 소프트웨어 검사는 해석해가 있는
단순 감쇠 ODE로 비교하고, 예산 안에서 일치하지 않을 때 보류하는지 확인했다.

펌프 곡선은 체적유량·수두에서 질량유량·압력차로 변환한 단위와 원래 출처를
검사했다. 실제 mapped pump의 운전점을 자체 곡선 계산과 비교하고, 큰 필요
NPSH를 부여한 별도 입력에서 원 엔진의 물리 적합성 실패가 보류로 유지됨을
확인했다. 이는 특정 기준 입력의 연동 검사이며 실제 펌프 성능 인증은 아니다.

## 사고 이력 교환 검사

사고 교환 검사는 별도 `research/release_exchange_results.json`에 있다. 일반
수소의 단일 출구·0.01초 기준 사례에서 PRISM native 패킷을 생성하고, 시계
오프셋 10초와 잔류 질량·동적 상태 근거를 보존했다. 0.005→0.0025초의 시간
간격 변화에서 누적 질량 차이는 약 4.05×10⁻¹⁹ kg였으며 선언한 10⁻⁷ 상대 및
10⁻¹² kg 절대 일치 기준을 통과했다. 작은 기준 사례의 수치 일치이며 긴 시간
방출·실제 관망·독립 실험 정확도를 증명하지 않는다.

파라수소의 유체명 오류, 2상 기체 밀도와 액체 도달 좌표 오류는 보류로 재현했다.
초기 품질 0·0.1·1의 포화 끝점/중간 사례를 실행했고 품질 1에서는 선언 상과
행 필드 형식이 다른 문제도 보류했다.
검사는 원본 값을 고쳐 성공시키지 않는다. 추가 계약 검사에서는 질량 누계·사건
ID·시계·상태 밀도·좌표·이력 해시가 바뀌면 전달을 막고, 측정에서 유래한 계산을
reviewed_measurement로 승격하지 않음을 확인했다. native 종료 문자열의 reviewed는
이 패키지의 물리 방호 승인이나 현장 검토를 뜻하지 않는다.

## 반복 검사와 재료 추세 연결

반복 검사는 알려진 좌표 이동·각도 0/2π 경계·새 관측·미등록 용접부·동일 비용의
분할 후보·행렬 예산·부분 읽기 차단을 검사했다. 깊이를 바꿔도 위치 정합 결과가
같아야 하며, 좌표 등록/정합 이력의 해시가 바뀌면 성장 연결을 거부한다.
명목 잔여 두께·시간·오차의 합성 선형 사례를 실제 Mat 추세에 전달해 기준
손실률과 비교했다. 원 모델의 통계 구간과 최악 계측 경계는 별도 보존한다.

실제 ILI 관측의 시각·계측 오차·정합 승인 누락은 needs_data이며 성장 함수를
호출하지 않는다. 전체 읽기와 선택 용접부의 후보 수는
`research/ili_application.json`에 기록한다. 이 결과는 전체 배관의 결함 정합
정확도·성장률·POD·파손확률 검증이 아니다. 입력 스키마 검색도 전체 재료 계산
검증으로 집계하지 않는다.

## 배포와 후속 검증 절차

`scripts/audit_release.py`가 실제 빌드된 wheel·sdist의 구성과 텍스트를 검사한다.
결과는 `research/release_audit.json`에 기록한다. 핵심 전용 환경의 실행 기록은
`research/core_installation.json`에 별도로 남긴다. CI 설정은 Windows/Linux에서
실행하도록 작성했으나 원격 CI의 성공을 이번 로컬 실행으로 주장하지 않는다.

후속 모델은 기준 문제·단위·보존량·시간/공간 수렴·독립 자료 검증을 먼저
정의한다. 수소·극저온·상변화·복잡한 과도현상과 실제 누설 성능은 추가 검증이
필요하다. 관측을 보정에 사용한 뒤 같은 자료로 독립 검증이라고 부르지 않는다.

## 성분 수송과 수력 판정 정정

성분 수송 관련 16개 검사를 추가한 단계에서 전체 97개를 통과했다. 단일 관의 이상적
체적/유량 이동시간과 출구 농도, 두 유입의 동일 유량 혼합, 일차 반응 지수해,
물 나이와 출처 비율을 비교했다. MASS/FLOWPACED/SETPOINT 단위, 기존 수요
주기·위상과 주입 사건 보존, 상위 시계 오프셋, 변조된 결과 전달 차단도 검사했다.

원 엔진의 MASS 주입에 대해 입력 단위계에 따른 미세한 차이를 확인했다.
직렬화를 L/s·수두 m로 통일해 기준 질량률을 유지했다. 물 나이의 단일 관
기준은 EPANET의 반올림된 체적 환산과 정확한 SI 체적/유량을 별도 기록한다.
동일 수치 판정 기준을 유지하며 원 응답을 사후 보정하지 않는다. 반응 시간
1초·2초의 차이와 해석해 허용 범위도 실행 요약에 있다.

수력 전용과 수송 경로를 한 실행기로 통합했다. 이전에는 binary 결과의
error_code와 접점 수지만 읽어 원 엔진의 반복 초과 경고를 누락했다. 이제
