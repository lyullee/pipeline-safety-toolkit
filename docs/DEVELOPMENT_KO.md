# 개발 과정과 설계 결정

## 2026-10-29: 유사 누수 자료 등록본 대조

사용자 제공 tbrnp6vrnj.1 집계 ZIP을 기존 xw44wv2g88.1 7z와 source-attributed로 재고했다. 282개 파일의 센서별 경로와 바이트 수가 모두 대응하지만 content hash는 아직 대조하지 않았다. 새로운 `leak_deposit_crosswalk`는 실제 파일의 경로·크기·SHA-256을 비교해 디지털 동일성만 분류한다. 공통저자/유사 메타데이터를 독립 실험으로 해석하지 않고 단위·교정·시계·사건 정답을 추론하지 않는다. ZIP 원본을 코드에 포함하지 않으며 publisher 변환 스크립트는 실행/배포하지 않는다. 합성 ledger 회귀는 작성했지만 실행은 누리온 대기다.
카탈로그 모델도 `guide`, 별도 SHA-256, Git repository blob SHA와 짧은 checksum provenance note를 표현하도록 보완했다. `_matches`는 선언된 checksum pin을 모두 검사한다. inventory rebuild는 카탈로그 등록 여부만을 기준으로 저장된 후보/취득 row를 삭제하지 않도록 고쳤고 회귀 1개를 작성했다. 정적 catalog parse는 56개 source row를 읽었다.

## 2026-10-29: 정체 potash 관 보호전류 자료 reader

CC BY 4.0 Mendeley V2 파일을 공급자 공개 API에서 다시 확인해 취득하고 SHA-256/길이를 대조했다. 별도 `potash_pipe_cp` reader는 공급 해시, OOXML 단일 표·헤더·20 시점·세 반복 및 0–95분 시간축을 확인하고 보고 평균/95% 구간과 반복 원값을 나눠 반환한다. A/m2 변환을 명시적으로 추가하되 원 통계는 계산하지 않는다. 소스 행은 공개 research 산출물에 복사하지 않았다. 합성 OOXML 회귀를 작성했지만 실행은 누리온 대기이며, 실제 원본 적용과 보호 전위·노출면적·온도·보호 기준의 검토가 남아 있다. 정체 파이프 자료와 유속 potash elbow 자료는 서로 다른 시험이다.

`to_signal_frames`를 추가해 공개 실험 시계열을 기존 `SignalFrame` 및 `EvidenceRef` 계약으로 매핑한다. 보고 평균과 단일 반복을 명시적으로 선택하며 CC BY 출처·해시·시험실 origin을 넘긴다. 면적이나 보호 기준을 채우지 않고, 기존 cathodic budget API를 호출해 설계값을 자동 생성하지 않는다. 어댑터 회귀는 합성 자료로 작성했으며 실행하지 않았고 누리온 대기열에 포함한다.

## 자료를 먼저 확보한 이유

관측의 단위·기준압·생성 방식·실험 분할을 확인하지 않은 상태에서 모델을
맞추면 검증 목적을 잃는다. 후보 22개를 조사해 12개 자료군 약 2.77 GB를 확보하고
원본 해시·조건·실패를 남겼다. 기존 로컬 캐시를 재사용해 중복 취득을 줄였지만
캐시 검증을 공급자 체크섬 검증으로 표시하지 않았다.

장시간 지연되는 묶음 다운로드를 확인한 뒤 원자적 부분 파일과 실행 한도가
있는 별도 프로세스로 변경했다. 진행 원장에는 고유 run ID를 부여해 여러
실행의 중간 기록이 충돌하지 않게 했다. HTTP 403은 우회하지 않고 실패를 보존했다.

## 계약·API·계산

엄격한 Pydantic 계약으로 숫자·단위·압력 기준·시계·근거·생성 방식을 명시했다.
가변 속성·결측·유효성을 같은 의미로 덮어쓰지 않게 했다. 등록 API는 입력
스키마와 출력 단위의 누락을 검사한다. JSON 구성은 코드를 임의 실행하지 않는다.

배관 계산 24개는 독립적인 기본식 또는 Fluids·ht·CoolProp의 명시적 어댑터로
구성했다. 물 관망은 WNTR/EPANET을 선택했다. 성숙한 공개 구현을 우선 사용하고,
새로운 기법은 기존 프로젝트의 후보와 동일한 분할에서 비교하는 정책을 정했다.
TSNet 0.3.1은 현재 NumPy 2에서 격자 생성에 실패했다. 소스를 복사·수정해
호환시킨 것으로 표시하지 않고 실패를 기록했다. 이후 단상 액체 특성선법의
파속 조정·분기 반사·접점 수지·체적수지·상 경계를 독립 구현하고 기준 파와
격자 세분화로 검사했다. 전체 밸브·펌프 동역학이 완성된 상태는 아니다.

기본 물성 외에 사용자 공급자도 주입할 수 있게 했다. 사용자 공급자의 ID와
버전을 요구하고 결과를 user_model로 남긴다. 제조사 계수와 현장 기준값은
검토된 입력으로 공급받으며 외부 표를 코드에 내장하지 않는다.

## 통합·판정·절차

계산 작업 흐름의 부모 결과가 유효하지 않으면 자식을 보류한다. 단위 일치가
물리적 동일성을 증명하지 않기 때문에 설비·포트 매핑의 책임을 문서화했다.
수치 계산의 완료와 사용자 기준 판정을 분리했다. 비수치 공법은 필수 근거와
선행 작업을 갖춘 현장 절차 기록으로 관리한다.

실제 Mat·모니터링·HRA 객체를 호출하고 스키마 차이를 수정했다. 개별 계산에서
보이지 않던 import 이름 충돌은 전체 검사로 발견했다. 변경 후 수학·계약·자료·
작업 흐름을 포함한 107개 검사를 통과했다. 실패 과정도 검증 문서에 남겼다.

기존 수소 장치 팩토리의 22개 모델 식별자와 필수 입력을 조회하는 클라이언트를
추가했다. 실제 관 계산·제한된 균질 평형 제어체적을 호출하고, 시간 세분화의
질량·에너지·벽온도 일치를 확인했다. 팩토리가 입력하지 않은 필드를 조용히
무시하는 사례를 재현해 기본 클라이언트 정책에서 거부한다. 이 조회 기능을
22개 물리 모델의 독립 검증 완료로 집계하지 않았다.

사용자 펌프 곡선의 체적유량·수두를 기존 장치의 질량유량·압력차 곡선으로
변환할 때 밀도와 중력을 명시한다. 해석 가능한 운전점을 비교하고 원 엔진의
NPSH 불충족 상태를 보류로 유지했다. native 결과의 파생 적합성 속성도 보존해
단순 직렬화가 원래 실패 판정을 누락하지 않게 했다.

이어 기존 `DynamicHEMPipe.export_accident_history`를 실제 PRISM 방출 빌더에
연결했다. 기체 기준 사례에서 누적 방출과 잔류 재고를 보존했고 시간 간격을
절반으로 줄인 질량 누계의 일치를 확인했다. 원본은 파라수소 유체명을 잘못
표시했고, 2상 분기에서 혼합 밀도를 기체 상태로 사용했으며, 액체 도달 위치를
방향처럼 정규화했다. 기존 수신 형식만으로는 이 오류가 차단되지 않았다.
원 이력과 근거를 남기고 이쪽 물성·좌표 검사에서 보류한 뒤 PI-X01에 요청했다.
단일 출구 이력을 양방향 파단·유한 구동·전체 위험 계산으로 집계하지 않았다.

## 반복 검사와 재료 추세 연결

반복 검사 판독기를 추가해 선택 용접부의 상대거리·원주각·mm 단위를 유지한
SI 관측을 생성했다. 전체 거리 원점과 불명확한 좌표 열을 정합에 사용하지 않고
사용자가 선언한 좌표 등록을 받는다. 메타데이터 행 수에 의존하지 않도록
읽기 전용 시트의 범위를 재설정하고 실제 XML 끝까지 읽는다. 캐시는 원본·요청·
판독 코드·관측 스키마·버전·내용 해시로 확인한다.

위치 기반 배정에는 미대응 선택·국소 모호성·용접부별 자원 예산을 추가했다.
실제 자료에 없는 동일 결함 ID·시각·계측 오차를 만들어 넣지 않았다. 승인된
합성 대응과 선형 손실을 기존 Mat의 추세 계산에 전달하고, 실제 자료의 미검토
성장 연결은 보류했다. 기존 재료 레지스트리의 조회 기능도 재사용했다.
실행 중 소유 모델 검색이 75개를 반환해 초기 범위에 없던 수소 속도 경계 모델
ID 하나를 외부 소유 항목으로 추가했다. 범위 목록은 197개가 됐으며 모델의
존재와 해당 모델의 수치·현장 검증은 별도로 관리한다.

## 배포 경계와 이어가기

원 코드·주석·설명은 독립적으로 작성했다. 외부 소프트웨어는 의존성과 명시적
어댑터로 사용한다. 원자료·변환 관측·수집 페이지·개인 환경은 공개 소스 경계에서
제외하고 출처·버전·권리·해시·집계만 보존한다. 출처 고지는 유지한다.

개발·사용·검증·확장 요청·후속 과제를 저장소에 남겨 대화 기록 없이 이어갈
수 있도록 했다. 현재 구현의 한계를 감추지 않고 37개 계획 항목과 29개 현장
절차 의존 항목을 명시한다. 원격 저장소 생성·공개·다른 프로젝트 수정은 이번
작업의 실행 내역에 포함하지 않는다.

## 성분 수송과 공통 EPANET 진단

일정 밀도 물의 희석 성분·일차 체적 소멸·물 나이·출처 비율을 WNTR/EPANET으로
연결했다. 주입의 kg/s와 kg/m³, 비율과 백분율, 초와 원시 시간 단위를 명시했다.
주입 절점 때문에 수요 패턴의 주기·위상이 바뀌지 않도록 공통 정수 초 격자로
재표현하고 패턴·반환 배열·단계 예산을 검사한다. 제품의 밀도·점도 변화나
다성분 반응 해석으로 집계하지 않는다.

성분 수송 적용 중 원 엔진의 수력 경고를 발견했다. 기존 순수 수력 경로는
해당 경고를 반환하지 않아 작은 수지 잔차만으로 computed가 됐다. 두 경로의
실행을 epanet.py로 합치고 매 수력 단계의 경고·수렴 통계·종료 시각을 판정한다.
공개 관망의 현 상태는 보류로 정정했다. 모든 성분 검사를 통과해도 수력 경고를
무시하지 않는다. 감쇠와 반복 한도 진단으로 경고가 없어지지 않은 사실을 남긴다.

주입 단위의 교차 확인에서는 일관된 L/s·수두 m 직렬화를 사용했다. 엔진의
반올림 단위 상수로 생기는 작은 이동시간 차이를 SI 해석해와 원 엔진 기준으로
구분했다. 원 엔진 수지 통계는 상수 번호 4이며 수요 감소 통계와 혼동하지 않게
명시했다. C 핸들·API 버전·라이브러리와 직렬화 입력·호출 코드 해시를 기록한다.

기존 모니터링의 metadata가 추가 문맥을 이미 지원하므로 새 저장소를 만들지

API로 보내려면 caller가 허용오차를 검토·승인해야 하며 해당 가정이 trace source digest에

`percussion_data` reader는 source hash/size, canonical member path, 목록 내 크기,
header, finite numeric values, sample/time budgets를 확인하고 selected member만 읽는다.
기존 `acoustics.SampledTrace`와 통합할 sensor/asset/clock ID는 자동 추론하지 않는다.
요약은 압력 범위·시간/표본 정보를 남기고 원 파형 값은 포함하지 않는다. RAR 전체

## 2026-10-29: 절차 검토시각 provenance 경계 강화

`ProcedureRecord.reviewed_at`을 timezone-aware `datetime`으로 바꾸고, timezone offset 없는 ISO 시각·날짜 문자열과 파싱되지 않는 값을 거부하도록 했다. 원 offset은 기록 직렬화와 digest에 들어간다. 이것은 입력 형식 검증일 뿐 reviewer identity/권한·시계 진실성·전자서명 인증은 제공하지 않는다. 관련 negative/positive 회귀를 누리온 targeted manifest에 추가했으며 실행은 연기했다.

보강: Python aware-datetime 동등성은 같은 순간을 다른 offset으로 표기한 값을 같다고 볼 수 있다. replay의 caller-record 비교는 Pydantic JSON 표현을 기준으로 바꿔 provenance offset 변경을 감지한다. 같은 instant/different offset 회귀를 추가했으나 로컬에서 실행하지 않았다.



## 2026-10-29: registry 사용자 callable 바인딩 provenance v3

기존 registry는 함수 text와 함수 module bytes를 지문 처리했지만 `functools.partial`, closure, 기본값, callable instance 상태를 놓칠 수 있었다. v3는 지원하는 JSON 상태와 해당 객체 클래스의 source module SHA를 digest에 추가한다. 함수가 참조하는 전역 바인딩과 bound method 소유 인스턴스도 캡처해 평가 도중 변경을 감지하며, 외부 객체나 모듈처럼 상태를 완전히 읽을 수 없는 경우는 `callable_binding_scope=partial`로 표시한다. 평가 전후 지문이 달라지면 결과를 거부한다. 입력값은 결과 metadata에 노출하지 않고 hash만 기록한다. 다섯 회귀 항목을 작성했으며 로컬 실행은 하지 않았다.

## 2026-10-29: 취득 당시 카탈로그·자산 provenance 고정
