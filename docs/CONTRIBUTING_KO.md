# 개발·검토 기여 안내

1. 해당 모델의 ID, 실제 API와 지원 영역을 먼저 찾는다. 기존 엔진 기능을 복제하지 않는다.
2. 버그 수정은 재현 입력과 기대 물리 의미를 함께 적는다. 일반화 범위를 불필요하게 늘리지 않는다.
3. typed request, 단위·시계·압력 기준, 결측과 signed 값을 유지한다.
4. 소유 엔진이나 데이터의 버전·라이선스·실제 import 경로를 확인한다. 출처가 불명확한 표·문장·계수를 넣지 않는다.
5. 계산식 검증, 독립 물리 기준, 경험계수 보정과 현장 적합성을 별도로 기록한다.
6. 코드 변경 후 관련 의미 있는 시험을 실행하고 소스/환경/JUnit/로그를 보존한다. 미실행을 통과로 쓰지 않는다.
7. source와 wheel 설치, 선택 의존성이 없는 core 설치의 차이를 확인한다.
8. API/모델 범위가 바뀌면 카탈로그·설명·예제·미완료 목록을 함께 갱신한다. source pin은 실제 변경 근거를 검토한 후에만 갱신한다.

공개 이슈에는 원자료나 계정 정보 대신 최소한의 합성 재현 입력을 넣는다. 문서·주석은 독자적인 설명을 쓰고, 제3자 라이브러리/데이터의 필요한 출처와 고지는 보존한다. 개인 참고 자료를 공개 소스에 옮기지 않는다.

정확성 오류 검사는 `python -m ruff check src tests scripts examples --select E9,F821,F822,F823`로 실행한다. 전체 스타일 검사는 별도 기술 부채를 드러내는 용도로 유지하며 경고를 묵살한0경고 통과로 표시하지 않는다.
